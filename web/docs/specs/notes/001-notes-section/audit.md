## Scope

`web/src/features/notes/**` and its wiring: `web/src/app/root/App.tsx` (routes `/notes`, `/notes/settings`),
`web/src/app/shell/sections.ts` (`moreSections`) and `SideNav.tsx`, `web/src/features/home/page/HomePage.tsx` (the
«Про нас» card for phones), `web/src/platform/query-client.ts` (`moduleKeys.notes`; `query-keys.ts` until the identity merge), `web/docs/architecture.md`
(Notes). Measured against `web/docs/rules.md`, `web/docs/design.md`, `web/docs/architecture.md`, the glossary, ADR
0006/0007/0009/0017 and the Todos feature as the reference implementation. No screenshots or runtime smoke run were
requested; the review is of the code, the tests and the checks.

## Method

1. Read the SDD, the backend design (operations, headers, error codes), the web rules, design rules, architecture,
   glossary and ADRs; read every production file in scope and each test file.
2. Checked: folder axiom (≤ 6 production files, no mixed or one-file folders), file sizes (components ≤ 150 lines,
   modules ≤ 200), one responsibility per component, feature isolation, API only through `*-api.ts` via
   `platform/api.ts`, React Query keys and invalidation, `Idempotency-Key` creation / reuse / renewal, `If-Match` on
   every edit and delete and which version it carries, 404/409 handling, pending locks, URL state, loading / empty /
   error states, accessibility basics (names, `aria-current`, valid content of buttons), Ukrainian texts, theme tokens,
   test coverage per TS-102…TS-106.
3. Fixed the local findings with a failing test first where behaviour changed, then ran the full check set.

## Step 0 — quality targets

`api/docs/architecture/quality-targets.md` exists with backend targets (read P95/P99 300/800 ms, write 400/1 000 ms,
all "not measured"); there are no client targets (AF-001), so no performance verdict is given. Proposed, to confirm:
`/notes` first usable list ≤ 2 s on a mid phone over 4G (Lighthouse mobile / Playwright trace on the deployed site);
quick add visible in the list ≤ 1 s after Enter (one POST plus the refetch, within the write and read P95 above).

## Checks that passed (no finding)

- **Folders and sizes:** ten folders of 2–6 production files each, no mixed, empty or one-file folders; largest
  component `NoteDialog.tsx` 133 lines, largest module `use-note-form.ts` 113 (structure check `lineLimits` green
  for the feature). Components split by responsibility: page, groups, card, quick add (+ `use-quick-add.ts`), dialog
  (+ `use-note-form.ts`, `NoteFields`, `SegmentedField`), filters, shared states; pure logic sits in `.ts` modules with
  tests.
- **Boundaries:** `features/notes` imports no other feature; only `data/*-api.ts` and `writes/*-api.ts` import
  `platform/api`; the signed-in person comes from `platform/member-api`, never from `features/identity`. Wiring touches
  only `App.tsx`, `sections.ts` (`moreSections`, rendered by `SideNav`), `HomePage.tsx` and `query-client.ts`.
- **React Query:** keys `['notes', 'items', query]` and `['notes', 'categories']` under `moduleKeys.notes`; every note
  and category write, and every stale (404 / 409) failure, invalidates `['notes']`; mutations are not retried; the list
  waits (`enabled`) for the member so the default tab is known before the first request.
- **Idempotency:** note create (quick add and dialog) uses `useIdempotencyKey`: same body → same key, changed body →
  new key, renewed after success and after a reused-key 409. New test: a failed quick add retried with Enter keeps the
  key, the next note gets a new one.
- **If-Match:** note save and delete, category save and delete send the version (AF-002, AF-008); 409 reloads, 404
  closes the note dialog with «Цієї нотатки вже немає…».
- **Pending locks:** quick add (Enter and «Додати»), dialog «Зберегти» and «Видалити», delete confirmations, category
  dialog; dialogs cannot be closed while a write is pending.
- **URL state:** `?about=&kind=&category=&q=` via `useSearchParams` (replace), unknown kind ignored, a name in `about`
  maps to the matching relative tab, «Скинути фільтри» keeps the tab, search debounced 300 ms.
- **States:** skeleton cards and a skeleton tab strip, designed empty tab text per person, filtered empty with
  «Скинути фільтри», error with «Повторити» on the list and in settings.
- **Design and language:** theme tokens and `mainChannel` tints only; kind marks pair colour with icon and word; icon
  buttons (add, detailed form, gear, category edit / delete) have `aria-label` and a tooltip; the dialog is full screen
  below `sm`; Ukrainian texts follow the glossary («Налаштування», «Додати», «Зберегти», «Скасувати», «Видалити»,
  «Повторити», «Пошук», «Категорії»); plurals through `Intl.PluralRules`.
- **Tests per SDD:** TS-102 — `notes-tabs.test.ts`, `filters.test.ts`, `note-form.test.ts`, `labels.test.ts`,
  `category-form.test.ts`, `note-groups.test.ts`, `failures-api.test.ts`; TS-103 — `NotesPage.test.tsx` (6 tests);
  TS-104 — `NoteDialog.test.tsx` (6 tests: create, edit, delete, 409 on save, 409 on delete, 404); TS-105 —
  `CategoriesSettingsPage.test.tsx` (3 tests); TS-106 — `AppLayout.test.tsx` (menu entry, bottom bar of five),
  `HomePage.test.tsx` (the `/notes` link), structure check.
