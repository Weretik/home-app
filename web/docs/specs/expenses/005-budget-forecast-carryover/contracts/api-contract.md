## Operations

| Intent      | Operation              | Request mapping                                                     | Success mapping                                  | Errors and visible result                                           |
| ----------- | ---------------------- | ------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| see plans   | `listPlannedExpenses`  | `?year&month` from the URL                                          | items + `totalAmount` → rows and «Запланировано» | load error with retry                                               |
| add plan    | `createPlannedExpense` | form → `{ year, month, name (trimmed), categoryId, payer, amount }` | invalidate `['expenses']` (ADR 0009)             | 400 → field messages; 409 → «уже отправляли», renew key; 429 → wait |
| change plan | `updatePlannedExpense` | same body, `If-Match: version`                                      | invalidate `['expenses']` (ADR 0009)             | 409 changed / 404 → message + reload                                |
| delete plan | `deletePlannedExpense` | id                                                                  | invalidate `['expenses']` (ADR 0009)             | 404 → reload                                                        |
| record      | `recordPlannedExpense` | `{ date, paymentMethod, comment                                     | null }`, `If-Match`                              | invalidate `['expenses']`                                           | 404 / 409 → message + reload |

## Client projection

- Defaults: plan payer «Общее» (`Shared`) unless the form says otherwise; record date today, method `Card`.
- Response validation: generated types only (compile time), as everywhere in the app.
- No paging for plans.
- Retries: 4xx not retried (query client); a create retry reuses the key.
- No auth yet.

## Contract verification

- `npm run contracts:generate`, then `npm run typecheck` (fails if a field is missing).
- CI checks the generated file matches the committed contract.
