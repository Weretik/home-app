Idempotency (step 3c): every create sends a key made once per form and data (`useIdempotencyKey`), reused on retry,
renewed after a 409 or changed data; every submit and delete is locked while pending (`EntryDialog`,
`DeleteEntryDialog`, `BudgetSettingsCard`); React Query does not retry mutations; no offline queue. No gap.

ADRs (step 3b): the key areas have accepted records (0001–0008); this audit adds 0009 (writes refresh the module) and
0010 (every rule has a check), amends 0007 and extends 0004. The web SPA is a container on the backend C4 diagram.

Feature review list (step 3d): access rights — none yet (open writes until sign-in, api ADR 0015); double-submit lock
✅; end-to-end test ❌ (no E2E in the project, SDD 001 GAP-W04 — open question below); docs and SDD updated ✅;
scenarios proved by page and unit tests ✅ (evidence recording open, AF-14).

## Open questions (product or backend; behavior not changed)

1. **Deletes without a version** (SDD 001 GAP-W02, api 001 GAP-001): `DELETE /expenses/{id}`, `/incomes/{id}`,
   `/savings/{id}`, `/budget/limits/{id}`, `/planned/{id}` take no `If-Match`, so a delete can remove a row someone
   changed meanwhile. Needs a backend contract change first; the web would then send the row's version.
2. **«ИТОГО» and percents computed in TypeScript** (SDD 004 GAP-W09, api 004 GAP-014): the «ИТОГО» row's left, percent
   and per day (`limits/limit-rows.ts`) and the payer shares are computed in the browser while the API computes the
   same for each limit in C#. Moving them into `MonthSummary` would make one source; it is a contract change.
3. **E2E** (SDD 001 GAP-W04): no end-to-end harness; the rules do not require one. Decide per feature (the frontend
   SDD template asks for it) or record "page tests only" as a decision.
4. **Quality targets** (AF-12): confirm the proposed numbers.

## Rule → check summary

The full table is in [rules.md](../../../../rules.md#rules-and-their-checks). Checked by a tool: `src/` areas,
six files per folder, folder shape (mixed, one-file, empty, wrapper), dump names, import direction, feature

`*-api.ts`, the client instance only from `*-api.ts`, the client through its index, no `fetch` / Axios /
second client (ESLint), generated code untouched (`contracts:check`), never indexed, no literal colours, logic has a
test, module-prefix invalidation (tests), change-only writes (types). Review only, with reasons: SDD-first process,
one responsibility under the limit, submit locked while pending, server state only in React Query, "only problems"
marks, Russian text and phone-first layout, the rest of the design rules, no secrets, ADR for lasting decisions.
