# API contract

- **Source:** `api/docs/contracts/openapi.json`, generated by the backend build; the web types in
  `src/api-client/generated/api.ts` come from `npm run contracts:generate` and are never edited. Only generated types
  are used (`Schema<'…'>`, `paths`); when the final names differ from the brief, the generated file wins.
- **Boundary:** every call goes through `api` from `src/platform/api.ts` inside a `*-api.ts` file and `apiCall`, which
  turns problems into `ApiError` (`status`, `code`, `fieldErrors`).

Generated schemas used: `ShoppingItemView`, `ShoppingList`, `AddShoppingItemsRequest`, `AddItemsResult`,
`UpdateShoppingItemRequest`, `FrequentItem`, `DepartmentMatch`, `DepartmentItem`, `UpdateShoppingDepartmentRequest`,
`KeywordItem`, `UpdateShoppingKeywordRequest`, `ShoppingSettingsView`, `UpdateShoppingSettingsRequest`,
`ShoppingSummary`. Differences from the brief, followed as generated: history pages by `page` / `pageSize` instead of
a cursor; department and keyword creates take an `Idempotency-Key`; nullable request fields (`departmentId`,
`urgent`, `icon`) are always sent.

## Errors

- 400: field errors under the fields (`name`, `quantity`, `note`, `keyword`, `cartKeepHours`, …), message in an
  `Alert`.
- 404 / version conflict: «изменили или удалили в другом месте», the list reloads.
- 409 on create: duplicate name / keyword or a reused `Idempotency-Key` (renew it); on delete of the fallback
  department: the API's message.
- 429: «Слишком много изменений подряд».

## Checks

`npm run contracts:generate` then `npm run contracts:check` (no diff), `npm run typecheck`.
