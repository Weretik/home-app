# C4 diagrams

Three levels: who uses the system, which deployable parts it has, and how the API is split inside.

## Context

```mermaid
flowchart TB
    family["Masha and Vitaliy<br/>expenses, shopping list, to-dos, gifts"]
    system["Home system"]
    scheduler["Scheduler<br/>calls the outbox tick (when a module needs it)"]
    sheet["Google Sheet «Учёт расходов»<br/>old expenses log, read once for the import"]
    operator["Operator<br/>runs the sheet import"]

    family --> system
    scheduler --> system
    operator -->|reads| sheet
    operator -->|"import on a local API, then the dumped rows as SQL (DBeaver)"| system
```

## Containers

```mermaid
flowchart TB
    family["Masha and Vitaliy"] -->|HTTPS| web

    subgraph system [Home system]
        web["Web app<br/>React SPA on Azure Static Web Apps, noindex"]
        api["API<br/>ASP.NET Core modular monolith on Azure App Service"]
        db[("PostgreSQL at the hosting provider<br/>database weretick, schema per module")]
    end

    web -->|"JSON over HTTPS, CORS"| api
    api -->|EF Core| db
    scheduler["Scheduler"] -->|"POST /internal/outbox/tick"| api
    actions["GitHub Actions<br/>build, tests, migration bundles, deploy"] -->|"migrations before deploy"| db
    actions -->|deploy| api
```


Update these diagrams in the same change that adds a module, an external system, or a new way of running work.
