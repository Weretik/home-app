# 0001. Один репозиторий, API одним проектом

**Статус:** принято, 2026-11-26

## Контекст

Проект основан на [fullstack-modular-template](https://github.com/Weretik/fullstack-modular-template): модульный
монолит с пятью проектами на модуль, медиатором, outbox, Nx и генерацией клиента из OpenAPI. Для семейного сайта
на двух пользователей это слишком много: каждая мелкая правка трогала бы много файлов.

## Решение

- Один репозиторий: `api/` и `web/` рядом, у каждой половины свой workflow с фильтром по путям.
- API одним проектом `HomeApp.Api`, фичи по папкам `Features/<Область>/`, Minimal API, без медиатора и Result-типов.
- Фронт на обычном Vite без Nx; API вызывается через один модуль `src/platform/api-client.ts`.
- Из шаблона оставлены: центральное управление версиями NuGet, `TreatWarningsAsErrors`, CORS из конфигурации,
  `/health`, docker-compose с PostgreSQL, Dependabot, правило «не больше 6 файлов в папке».

## Последствия

Код проще читать и менять. Если какая-то область разрастётся (например, расходы с ИИ-разбором чеков), её можно
вынести в отдельный проект по образцу шаблона. Типизированный клиент из OpenAPI можно добавить позже, когда эндпоинтов
станет больше пяти-шести.
